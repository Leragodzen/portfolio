# Сайт-портфолио Валерии Левановой

Одна страница для холодной рассылки и фриланс-чатов: работы, сроки, цены, вопросы.
Чистый HTML/CSS/JS, без сборщиков. Публикуется на GitHub Pages.

## Файлы

```
index.html            главная страница
oferta.html           договор оферты
privacy.html          политика конфиденциальности
assets/style.css      стили
assets/app.js         липкая кнопка, рельс, переписка, плашка cookie
assets/metrika.js     Яндекс.Метрика и цели (номер счётчика в первой строке)
assets/works/*.jpg    скриншоты клиентских сайтов, 390px-вьюпорт
assets/reviews/*.jpg  переписка с отзывами
assets/og.jpg         картинка превью для мессенджеров
assets/valeria.jpg    фото в блоке «обо мне»
demo/                 демо-версии для клиентов до оплаты
ЧТО ЗАПОЛНИТЬ.md      что осталось подставить
```

## Публикация

Двойной клик по `Опубликовать портфолио.command` на Рабочем столе.

## Как выложить новое демо

1. Создай папку `demo/название/` (латиницей, например `demo/kafe-vesna/`).
   Адрес будет `pixellord.ru/demo/kafe-vesna/`. Отдельные репозитории
   с адресами на github.io для демо больше не заводим.

2. В `<head>` каждой страницы демо добавь две строки:

   ```html
   <meta name="robots" content="noindex, nofollow">
   <link rel="stylesheet" href="/demo/demo.css">
   ```

3. Перед `</body>` вставь содержимое `demo/plashka.html`.

4. В самое начало файла, до `<!doctype html>`, вставь строку из `demo/shapka.html`.

5. Проверь перед отправкой:
   - плашка видна и на телефоне, и на компьютере, и не закрывает контент;
   - в `<head>` стоит `noindex, nofollow`;
   - папка `/demo/` закрыта в `robots.txt` (уже закрыта, менять не нужно);
   - ссылки внутри демо работают.

6. Опубликуй портфолио обычным способом и отправь клиенту ссылку
   `https://pixellord.ru/demo/название/`.

## Как превратить демо в боевой сайт после оплаты

1. Убери из `<head>` строку `<meta name="robots" content="noindex, nofollow">`
   и подключение `demo.css`.
2. Убери плашку демо перед `</body>` и комментарий в начале файла.
3. Поставь подпись автора в подвал: фрагмент лежит в `podpis.html`.
4. Перенеси файлы в отдельный репозиторий или на домен клиента.
5. Проверь, что страница открывается и ничего не съехало.
